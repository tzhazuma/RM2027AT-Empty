# 接口使用说明

面向 Application 层调用者。本文按当前 `Bsp/Inc` 与 `Components/Inc` 公共头文件说明可调用的接口；它是使用指南，不替代[API设计说明](API设计说明.md)中的设计约定。接口存在不代表硬件已验证。当前未声称工程已构建或完成板级验证。

## 1. 启动与用户入口

生成的 `main()` 先配置系统时钟、NVIC、GPIO、ADC、CAN、PWM 定时器以及 USART6 DMA；随后按顺序执行：

1. ATWP 生成的基础初始化（`wk_system`、`wk_gpio`、`wk_adc`、`wk_usart*`、`wk_can`、`wk_tmr*`、`wk_dma*`、`systick_interrupt_config()`、`wk_nvic_config()`）。其中 `wk_usart6_init()` 已使能 USART6 的 IDLE 中断与 DMA 接收，但此时 UART 帧队列尚未建立，`uart_irq_handler` 会走"队列未就绪"分支只清标志。
2. `bsp_init()`：依次初始化 PWM、LED、CAN、UART（建立静态帧队列）、ADC。不可恢复错误会直接调用 `panic()`。
3. `main()` 依次调用 `motor_tt_init()`、`motor_dji_init()`、`servo_init()`、`remote_init()` 初始化组件；`remote_init()` 返回非 0 时 `panic(FAULT_INIT)`。它注册 USART6 接收回调，并把串口配置为 DR16 默认模式（反相 RX、100000 baud、8E2），后续按空闲包长分发 DBUS/SBUS。
4. 由 `main()` 用静态栈/TCB 创建唯一默认应用入口 `robot_main(void *args)`，最后 `vTaskStartScheduler()` 启动调度器。

`xTaskCreateStatic()` 失败时调用 `panic(FAULT_INIT)`；调度器异常返回时调用 `panic(FAULT_SCHEDULER)`。在 `robot_main` 中只编写机器人应用逻辑；不要再次初始化这些模块。框架自带的常驻任务有：`uart_rx`（UART 回调任务，优先级 5）、`motor_dji`（优先级 5，首次注册电机时创建）、`daemon`（优先级 4，调用 `daemon_enable()` 后创建）；应用不需要自己创建这些线程。

```c
void robot_main(void *args)
{
    dbus_t remote;
    (void)args;

    for (;;) {
        if (dbus_get(&remote) == 0 &&
            remote.valid && remote.online) {
            /* 在此处理业务。 */
        }
        os_delay(10U);
    }
}
```

`os_createTask()` 是 Application 可用的动态线程创建接口（失败返回 NULL）；BSP/Components 内部任务使用静态资源。当前 `os.h` 实际提供的接口只有：`os_createTask`、`os_deleteTask`、`os_getTime`、`os_delay(ms)`、`os_delayUntil(&last_wake, period_ms)`、`OS_WAIT_FOREVER` 与优先级枚举 `os_task_priority_t`（`OS_TASK_PRIORITY_LOW/NORMAL/HIGH`）。`os_getTime()` 返回毫秒时间戳（uint32，约 49.7 天回绕，比较请用无符号差值）。不要在 ISR 中调用这些任务接口；需要从 ISR 通知时直接用 FreeRTOS 的 `vTaskNotifyGiveFromISR()` / `portYIELD_FROM_ISR()`。

## 2. DBUS 快照

`dbus_get(&out)` 返回一致拷贝，不暴露内部状态。调用前由 `main()` 完成 `remote_init()`；输出参数不能为空。返回 `0` 表示查询成功，`-1` 表示查询失败；成功后还要检查 `valid` 与 `online`。从未收到有效帧时 `valid=false`；超过 100 ms 未收到有效 DBUS 帧时查询结果会令 `online=false`，最后一次有效字段仍保留，不能当作新鲜输入继续控制。

- `channel[0..3]` 经过死区处理并限于 `[-1,1]`。
- 开关值为 `DBUS_SWITCH_UP/MIDDLE/DOWN`；未识别值是 `DBUS_SWITCH_UNKNOWN`。
- `timestamp_ms` 是接收帧的时刻；`sequence` 每次有效更新递增。
- 鼠标、按键、拨轮字段来自同一个 18 字节有效帧。

DBUS 任务仅接受长度为 18 且无 UART 错误标记的帧；协议字段非法的帧不更新快照。
DBUS 初始化配置非法或通道归一化计算出现非有限结果时会调用 `panic(FAULT_ASSERT)`，该路径会停机并关闭 PWM 输出。

电脑普通 TTL 串口模拟遥控器时，在 `remote_init()` 之后调用 `dbus_useUartInstead(true)`，配置非反相 RX、100000 baud、8N2；传入 `false` 恢复 DR16 的反相 RX、100000 baud、8E2。建议在 `main()` 用户代码区、启动任务和发送数据之前配置；切换时输入源应停止发送，不支持连续收帧中的无损切换。重新调用 `wk_usart6_init()` 会恢复默认反相设置。PC 模拟模式需发送 18 字节二进制 DBUS 帧并保留帧间空闲间隔。普通 3.3V TTL 转串口的 TX 直连 PA5、GND 共地；若板端接口有硬件反相电路，需要按实际电路选择。

```c
remote_init();
dbus_useUartInstead(true); /* 使用电脑普通 TTL 串口模拟 DBUS */
```

`remote_init()` 固定执行与 `dbus_useUartInstead(false)` 相同的完整配置，默认使用 DR16 模式，不需要额外调用 `false`。模式配置函数在初始化后使用。

## 3. 执行器当前状态

六路 `motor_tt` 与六路 `servo` 的 API 已实现且可调用，但其中写入的电机驱动电平规则与舵机脉宽/角度范围是**尚未核对的固定假设值**：

- `motor_tt_init()`、`servo_init()` 完成禁用状态初始化。注意：`motor_tt_enable()` / `motor_tt_setDuty()` 与 `servo_enable()` / `servo_setPulse()` / `servo_setAngle()` **当前会被执行并立即驱动 PWM 输出**，固件中不存在"未标定即忽略调用"的保护。
- `motor_tt_disable(id)` 立即停单路电机（占空比归零、两输入置低并清除使能）；`motor_tt_setDuty(id, ratio)` 的 `ratio` 必须有限且位于 `[-1,1]`，且只在已 `motor_tt_enable()` 后生效，enable 会先输出零占空比。当前没有状态查询接口。
- `servo_disable(id)` 关闭通道并清除旧目标；`servo_setPulse(id, us)` 接受 500..2500 µs、`servo_setAngle(id, deg)` 接受 0..180°、`servo_setDuty(id, duty)` 接受 0.025..0.125，三者都要求该通道已 `servo_enable()`；`servo_enable()` 从 1500 µs（该映射下为 90°）开始输出，重新 enable 不恢复旧目标。当前没有状态查询接口。
- 大疆电机通过 motor_dji_register(&motor, &config) 注册，motor_dji_setCurrent(&motor, current) 设置电流，motor_dji_stop(&motor) 停止，反馈直接读取 motor.measure。电机对象须保持地址稳定，未注册设备不启动服务任务。

RZ7889 停机/换向电平、CN10 方向以及舵机脉宽/角度范围都需按器件资料核对后才能接实际执行器；在核对完成前不要在业务代码里使能执行器。不要通过绕过组件直接改 PWM 来驱动电机或舵机。

## 4. BSP 常用接口

### CAN

`can_send(bus, &frame)` 发送标准/扩展数据帧或远程帧，DLC 为 0..8；标准 ID 不超过 `0x7FF`，扩展 ID 不超过 `0x1FFFFFFF`。它只尝试投递到硬件邮箱，不等待发送完成；无空邮箱资源忙时直接忽略。`can_receive(bus, &out)` 是非阻塞接收：有帧时返回 `0`，队列为空返回 `CAN_RECEIVE_EMPTY`（`-1`），总线错误返回 `CAN_RECEIVE_ERROR`（`-2`）；收到 `-2` 表示该总线发生错误，应撤销这条总线上电机的输出。总线参数为 `CAN_BUS_1` 或 `CAN_BUS_2`。CAN RX 时间戳单位 ms。

### UART

当前仅 UART_6 可收帧（USART6，DBUS 与 SBUS 共用）；UART_1/UART_7 调用被忽略。`uart_receiveFrame(UART_6, &frame, timeout_ms)` 按 IDLE 帧边界接收，成功返回 `0`，无帧、非法参数或超时返回 `-1`；注册了 UART 回调后该接口只允许回调任务调用，普通任务请用 `uart_register` 回调或协议快照接口。超时单位 ms，`0` 表示立即检查，`UINT32_MAX` 可无限等待（须调度器运行）。`uart_frame_t` 含最多 64 字节、长度、接收时间戳和错误位。错误位可为 `UART_ERROR_PARITY/FRAMING/OVERRUN/OVERFLOW`；应用应丢弃带错误的帧。

`uart_read()` 当前没有实现字节流读取，USART6 返回 `0`；`uart_write()` 当前未实现，USART6 返回 `0`。

### LED、ADC、PWM 与 BSP 状态

- `led_set(LED_1..LED_3, on)` 控制三颗红色 LED；编号与板上顺序相同（LED_1=PC13、LED_2=PC14、LED_3=PC15），`true` 点亮。另有 `led_on(id)` / `led_off(id)` 两个便捷接口；`bsp_init()` 会把三路 LED 置灭。
- `adc_sample(&sample, timeout_ms)` 读取 PA2 / ADC 通道 2 的一次转换。超时单位 ms，必须为正值且从调度器运行的任务调用；输出包含 `raw`、`full_scale`（4095）及采样时间戳。超时或转换重叠时返回 `-1`，成功返回 `0`。
- `pwm_setDuty(channel, duty)` 接受有限 `[0,1]` 的占空比，18 路通道都可写（不限于舵机通道）；写 0 会把该引脚强制回低电平输出。`pwm_disable(channel)` 关闭单通道，`pwm_shutdown()` 关闭全部通道（`panic()` 内部也会调用它）。成对更新与使能状态由组件（`motor_tt` / `servo`）负责，应用不要用 PWM API 绕开组件与上板核对。
- `bsp_init()` 初始化板级驱动；固定引脚和定时器映射由驱动内部管理。`panic(reason)` 关闭全局中断、强制 PWM 输出低、关闭三颗 LED 并永久停机，只用于不可恢复的初始化/断言/栈溢出/调度器/硬件故障路径。

## 5. 错误处理

框架不定义统一状态码。可恢复的无效参数、模块未就绪、资源忙、队列为空、超时和未实现操作直接忽略；有结果的接口返回 `int`：成功为 `0`、失败为 `-1`；谓词接口使用 `bool`。UART 字节接口返回实际字节数（当前未实现时为 `0`）。应用按需检查查询结果，并避免使用过期输入。

不可恢复的初始化配置错误、静态资源分配失败、内部状态不一致、断言、栈溢出、调度器故障和硬件故障直接调用 `panic(reason)`，关闭 PWM 并停机。有限超时参数以 ms 计；`uint32_t` 时间戳可能回绕，应采用无符号差值计算间隔。输入丢失、离线或超时时，应用应按控制策略停止相关输出；DBUS 恢复后不会自动重新使能电机。

## 新增接口

- `dbus_waitData()`：等待调用之后发布的有效新帧，返回本次等待耗时（ms）。无超时；未初始化或调度器未运行返回 `UINT32_MAX`。使用 os_getTime() 测量毫秒耗时，每个 RTOS tick 检查新帧，当前唤醒粒度为 1 ms。随后用 `dbus_get()` 读取快照。不得在 UART 回调中阻塞等待。
- `servo_setDuty(id, duty)`：实际 PWM 占空比，50 Hz 下范围 0.025–0.125，对应 500–2500 μs。须先 enable；非法值忽略。
- `can_register(bus, id, extended, callback, context)`：直接注册回调，最多 16 项；禁止重复总线/ID/格式。匹配帧进入任务回调队列，未匹配帧供 can_receive 使用。不要注册 DJI 已使用的反馈 ID。队列满只记录丢帧。
- `uart_register(id, callback, context)`：直接注册回调；当前仅支持 UART6，每口一个接收者。注册后直接 receiveFrame 被拒绝。DBUS 初始化时已注册 UART6。
- 两种注册接口初始化后调用，成功返回 0，参数非法、重复或容量不足返回 -1，无注销接口。回调在任务中执行，应及时返回；帧指针只在回调期间有效，context 须长期有效。
- `pwm_shutdown()`：替代 pwm_disableAll，关闭全部 PWM；后续显式设置可恢复输出。

## Daemon 在线监测（单例）

```c
#include "daemon.h"

daemon_enable(100); /* 设置超时为 100 ms，成功返回 0。 */
daemon_reload();    /* 收到有效数据后喂狗。 */
bool online = daemon_isOnline();
```

仅保留一份全局状态，无对象或配置结构体。启用后创建内部静态监测任务。enable 初始离线，reload 转为在线；超时查询返回 false，reload 恢复在线。重复 enable 更新超时并重置为离线。超时范围 1–INT32_MAX ms，非法值返回 -1 且状态不变。未启用时 reload 无操作、查询返回 false。接口用于任务上下文。应用可调用 reload 喂狗；dbus_get 成功获取有效且在线的遥控器数据时也自动喂狗，无效或离线数据不喂狗；原有电机反馈和命令超时保护仍保留。

启用 daemon 会立即清零 DJI 电机目标，DJI 电机保持关闭，直到应用第一次 reload。在线超时后内部任务每 tick 检查并清零全部已注册 DJI 电机电流目标，DJI 零电流帧由其服务任务提交；这不切断电调供电，CAN 故障时无法保证零电流帧送达。离线期间 DJI setCurrent 拒绝输出，TT 输出不受 daemon 影响。reload 只恢复控制许可，DJI 需在线反馈和新的 setCurrent。尚未调用 enable 时维持原有电机控制行为。后台检查优先级为 4，每次延迟 1 tick；实际响应受调度影响。
### Daemon 离线回调

```c
static void on_offline(void *context)
{
    (void)context;
    /* DJI 电机目标已清零，在此执行其他离线处理。 */
}

daemon_registerCallback(on_offline, NULL);
```

单例仅保留一个回调，重复注册替换，传 NULL 注销。enable 或 reload 后超时触发一次，持续离线不重复触发；enable 初始离线不立即回调，须经过完整超时。回调在监测任务中、清零 DJI 目标后、临界区外执行，应及时返回。注册不改变在线状态或计时。回调已被监测任务选中后，新的 reload 或注销不会取消此次调用；context 须保持有效直至正在执行的回调结束。
